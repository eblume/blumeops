# git-mirror — static public forge mirror (staging)

Read-only mirror of the allowlisted public repos, served from this fly app
by `server_name blumeops-proxy.fly.dev` in `fly/nginx.conf`. Part of
[eblume/blumeops#1208](https://forge.eblu.me/eblume/blumeops/issues/1208):
`forge.eblu.me` will become this static site at the cutover PR; today this
vhost on the app's free `blumeops-proxy.fly.dev` hostname is the staging
surface where the whole path is verified before the flip.

- **Browse:** static HTML generated by stagit (Alpine community `stagit`
  1.2, the C version) — `log.html` / `files.html` / `refs.html` /
  `commit/<oid>.html` / `file/<path>.html` per repo, `index.html` at the
  site root. Browsers pass an Anubis proof-of-work challenge (second
  instance, `127.0.0.1:8924`); git/API clients pass straight through.
- **Clone:** git dumb HTTP — `git clone https://…/eblume/<name>.git`,
  served statically straight from the volume by the edge vhost's
  `/eblume/*.git` location (no Anubis hop). The URL shape is byte-for-byte
  what today's `forge.eblu.me` clone URLs are, so existing consumers
  (e.g. the `hephd` self-update, the talos nix fetch) survive the cutover
  unchanged.

## Push path

Forgejo **push mirrors** on the private forge push into bare repos here.
The private forge's push-mirror sync pushes over SSH to:

```
git@flyio-proxy.tail8d86e.ts.net:/volume/git-mirror/repos/eblume/<name>.git
```

- **Reconnecting address:** the fly node's tailscale node key is
  persisted on the volume (`/volume/tailscale`, bind-mounted over
  `/var/lib/tailscale` in `fly/start.sh`), so a boot reconnects with
  the existing identity — no re-auth with the auth key. The key is
  minted ephemeral (`pulumi/tailscale`), so a long-offline node is
  reclaimed by Tailscale and its boot re-auths with the key; a
  non-ephemeral key, if we want a truly stable name, goes in the
  push-wiring PR.
- **Reachable, not public:** the in-VM `sshd` is delivered by WireGuard
  directly to the node's Tailscale IP — the public internet has no route
  to it at all (no public `:22` service). Until the push-wiring PR adds
  the tailnet ListenAddress + ACL grant, sshd listens on loopback only. (No
  `tailscale serve`: the tailnet has no autoAppCaps policy, and the
  `tag:flyio-proxy` node receives tailnet traffic on its CGNAT IP natively.)
- **Credentials:** the private side holds the push-mirror **private**
  keys (auto-generated by Forgejo, stored in its DB, backed up by
  borgmatic). The fly side holds the **public** keys in
  `fly/git-mirror/authorized_keys` (committed here — a public key is not a
  secret). Nothing credential-bearing reaches the fly machine, and the fly
  machine has no read path to the private forge: the push direction is
  forge → fly only.
- **ACL:** `src tag:forge → dst tag:flyio-proxy, tcp:22` (added by the
  push-wiring PR, with its ACL test block). The git-shell account is
  `mirror` with a forced `git-shell` command — authorized keys can run
  git push only, no login, no shell.

## Layout on the volume

```
/volume/
  tailscale/            # node key (bind-mounted over /var/lib/tailscale)
  ssh/                  # ssh host keys (copied into /etc/ssh, start.sh)
  git-mirror/
    repos/eblume/<name>.git   # bare repos (push targets)
    site/                   # stagit output (served)
      index.html style.css logo.png favicon.png
      eblume/<name>/…       # one directory per repo
```

`repos` in this directory is the allowlist (one `eblume/<name>` per line,
no comments — the Dockerfile COPYs it verbatim into the image).
Adding or dropping a repo = edit that file + add/remove the forge push
mirror; the next deploy regenerates the site from whatever is in
`repos/`.

## Cutover note

The `baseurl` in `create-mirror.sh` and
`post-receive` (the clone URL stagit prints and the atom feed links)
is the staging hostname. When `forge.eblu.me` flips to this site,
rewrite it to `https://forge.eblu.me`, update each repo's `url` file,
and regenerate.

## Operations

1. **First deploy:** `mise run fly-setup` (provisions the empty
   `git-mirror` volume; idempotent) **before** the deploy (`deploy-fly` warrant) —
   a machine declared with a `[[mounts]]` block that has no volume
   fails to start. On boot, `fly/start.sh` runs
   `fly/git-mirror/create-mirror.sh`, which creates the bare repos,
   installs the `post-receive` hook, and generates the initial (empty)
   site. Until the push-wiring PR lands, the repos are empty — the
   site shows an index with no rows and clones return an empty repo.
2. **After push wiring:** commit the public keys into
   `fly/git-mirror/authorized_keys`, deploy, create the push mirrors
   (the `mise` task in that PR), push a throwaway branch, and verify
   stagit output + `git ls-remote` over the public URL.
3. **Machine replacement:** the volume reattaches; init re-runs; the
   tailscale identity persists. Nothing to do.

Verification of the staging vhost (public vantage, post-deploy):

```sh
curl -s  https://blumeops-proxy.fly.dev/                          # 200, stagit index page
curl -s  https://blumeops-proxy.fly.dev/eblume/blumeops/          # 200, repo log page (index.html)
curl -sI https://blumeops-proxy.fly.dev/eblume/blumeops/issues/1  # 302 → forge.ops.eblu.me
curl -s  https://blumeops-proxy.fly.dev/eblume/blumeops.git/info/refs   # 200 after first push
git ls-remote https://blumeops-proxy.fly.dev/eblume/blumeops.git main  # after first push
```
