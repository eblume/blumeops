# Build Authentik from Source

Custom Nix derivation that builds authentik from source, replacing the `pkgs.authentik` nixpkgs dependency. This gives full version control independent of the nixpkgs release cycle.

## Motivation

Build Container CI resolves `<nixpkgs>` from the in-repo pin in `containers/flake.lock` (currently `nixos-26.05`; bumps are reviewed blumeops PRs, never automatic). That channel lags behind upstream authentik releases. Building from source lets us target any release by updating `sources.nix`.

## Architecture

`containers/authentik/default.nix` assembles the container image from four components:

1. **Web UI** (`webui.nix`) — Lit-based TypeScript frontend built with esbuild + rollup; its `@goauthentik/api` bindings come from `client-ts.nix`, generated from `schema.yml` (OpenAPI)
2. **Python backend** (`authentik-django.nix`) — Django application with 60+ Python dependencies installed via `uv` from PyPI (see [[authentik-nix-build-components#Python Backend]])
3. **Go server** (`authentik-server.nix`) — HTTP server binary that serves the web UI and spawns gunicorn for Django; Go API bindings generated by `client-go.nix` from `schema.yml` are vendored into its module
4. **`ak` wrapper** — a script in `default.nix` that sets PATH/VIRTUAL_ENV and delegates to `lifecycle/ak` (from upstream), which dispatches `server` to the Go binary and everything else to Python/Django

**Python packaging strategy:** Nix provides the Python 3.14 interpreter and system libraries. Python packages are installed from PyPI using `uv`, locked by authentik's `uv.lock`. This avoids nixpkgs' Python 3.14 compatibility issues and aligns with upstream's build process.

## Source

Sources are fetched with `pkgs.fetchgit` (SRI hashes) from forge mirrors for supply chain control:
- https://forge.ops.eblu.me/mirrors/authentik.git (upstream: `goauthentik/authentik`)
- https://forge.ops.eblu.me/mirrors/authentik-client-go.git (upstream: `goauthentik/client-go`)

The one exception is the `opencontainers` Python library — an upstream `uv` git dependency that `authentik-django.nix` fetches from GitHub. Version and hashes are centralized in `containers/authentik/sources.nix`.

## Updating to a New Version

1. Update `version` in `sources.nix` and `default.nix`
2. Update `src` and `client-go-src` hashes in `sources.nix` (use `nix-prefetch-git` on ringtail)
3. Rebuild `python-deps.nix` FOD — hash changes when `uv.lock` changes
4. Rebuild `webui-deps.nix` FOD — hash changes when `package-lock.json` or platform-specific npm binaries change
5. Recompute `vendorHash` in `authentik-server.nix` if Go dependencies changed
6. Test on ringtail: `nix-build test-build.nix -A assembled`
7. Build and push the container via CI

## Testing

Nix derivations target `x86_64-linux`. Test incrementally on ringtail:

```fish
set tmpdir (ssh ringtail 'mktemp -d /tmp/authentik-test.XXXXXX')
scp containers/authentik/*.nix ringtail:$tmpdir/
ssh ringtail "cd $tmpdir && nix-build test-build.nix -A assembled --extra-experimental-features 'nix-command flakes'"
ssh ringtail "rm -rf $tmpdir"
```

`test-build.nix` provides both individual component targets and a fully-wired `assembled` target.
