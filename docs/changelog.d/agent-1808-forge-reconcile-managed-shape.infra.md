forge-reconcile now accepts the one-fork-model repos.json shape — per-repo `managed: true` plus a top-level `excluded` name list, alongside the legacy `access`/`pool` shape (refusing both, neither, and mixed files). In the managed shape the reconciler owns the bot's forks: every managed repo must exist as `<collaborator>/<repo>` with the right parent and stay in sync (created and synced by a run passed `--fork-token`, which must be the collaborator user's; the CI token skips the half loudly), and `--check` fails on any eblume non-fork repo in neither list. Under the currently live legacy shape the new machinery is dormant, so merging changes nothing (eblume/blumeops#1808).
