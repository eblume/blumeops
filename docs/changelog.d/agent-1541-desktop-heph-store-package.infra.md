The ringtail eblume desktop heph spoke now runs the same nix-store heph package as the agent spoke (the `hephaestus` flake input, pinned to v1.10.7) instead of the `cargo install` oneshot: the `eblume-heph-install` oneshot/timer, the spoke's path unit, `hephTag`, and the install machinery in `heph-common.nix` are gone; the session shims and sway popover launcher re-point at the store bin dir (its `heph-quickadd` carries its own GUI lib-path wrap), and the spoke starts at boot like any other service. This also clears the hand-built pre-v1.8.0 `~/.cargo/bin/heph-quickadd` drift. Part of [eblume/blumeops#1541](https://forge.ops.eblu.me/eblume/blumeops/issues/1541).
