The ringtail borgmatic dump endpoint no longer aborts the talos-data and paperless-media tar dumps when the in-pod GNU tar exits 1 on "file changed as we read it" (tolerated only when kubectl's "command terminated with exit code 1" line is on stderr, so kubectl transport errors still fail), and the talos-data tar now excludes session-index.sqlite (a derived cache over the session jsonl that rebuilds on cold start) so a mid-write copy can no longer be torn in the archive.
